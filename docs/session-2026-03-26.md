- Share-Links (`https://divide-it.app/#/r/TOKEN`) ohne Login oder Registrierung

- Globale Passwort-Auth nur noch im `selfhosted`-Mode aktiv
- Ein-Codebasis-Ansatz: Verhalten über `MODE`-Env-Variable gesteuert

- Automatische Bereinigung abgelaufener Rooms aus der Liste

### 3. E-Mail-Zusendung via Resend
- Beim Erstellen einer Gruppe optional Email-Adresse angeben
- Link wird automatisch an die angegebene Email zugeschickt
- Domain `divide-it.app` in Resend verifiziert (SPF, DKIM, DMARC)
- Absender: `noreply@divide-it.app`

## Herausforderungen & Lösungen

### SQLite Migration schlägt still fehl
**Problem:** `ALTER TABLE ADD COLUMN room_token TEXT UNIQUE` scheitert lautlos —
SQLite erlaubt kein `UNIQUE` bei `ADD COLUMN`.
**Lösung:** `UNIQUE` aus der Migration entfernt; Constraint bleibt nur im
`CREATE TABLE` für neue Datenbanken erhalten.

### Docker Image vs. lokaler Build
**Problem:** `docker-compose.saas.yml` verwendet `image: ghcr.io/...` ohne
`build`-Section. `--build` Flag hatte keine Wirkung, Container lief immer mit
dem alten Image.
**Lösung:** Explizit `docker compose pull` vor `up` ausführen damit das neue
Image von ghcr.io gezogen wird.

### Service Worker cached alte `index.html`
**Problem:** Nach dem Hinzufügen des Umami-Scripts war es im Browser nicht
sichtbar — der PWA Service Worker servierte die gecachte alte Version.
**Lösung:** Browser-Cache über DevTools → Application → Clear site data leeren.
Dauerhaft gelöst durch korrektes Vite-PWA Cache-Busting beim Build.

### Port-Belegung beim lokalen Testen
**Problem:** Port 3000 war beim Starten des Backend-Dev-Servers bereits belegt.
**Lösung:** Prozess per `lsof -ti:3000 | xargs kill -9` beendet.

### GitHub Actions baut falschen Branch
**Problem:** Actions-Workflow war initial nur für `main` konfiguriert, `saas`
Branch wurde nicht gebaut → `ghcr.io/haenrick/divide:saas` existierte nicht.
**Lösung:** Workflow um `saas` Branch erweitert, separates Image-Tag `:saas`.

### `npm ci` schlägt im Docker Build fehl
**Problem:** `vite-plugin-pwa` hat einen Peer-Dependency-Konflikt mit Vite 8.
**Lösung:** `--legacy-peer-deps` Flag im Dockerfile ergänzt.
